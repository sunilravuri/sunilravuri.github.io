The Platform

From the offer letter to the paid invoice.

Every staffing workflow runs on one platform. Each one has its own state machine, permissions and audit trail, and six roles each get a view scoped to them, from admin and HR/finance down to employees and client approvers.

Employee Onboarding & Records

A seven-tab onboarding profile, plus quick add and bulk CSV import. Uploaded documents are read by AI, and an employee can only be activated once four conditions pass. The document vault keeps versions, and offers are signed electronically.

  • Document vault
  • E-signatures
  • Benefits & 401(k)

AI-Verified Timesheets

Employees submit weekly time with a screenshot from the client's system. Claude Vision reads the screenshot, and the timesheet can't be submitted unless the hours match exactly. Holidays are tagged automatically, and approvals move from manager to client PM.

  • Vision hour-matching
  • Approval chain
  • PDF export

Invoicing & Expenses

Invoices are generated from approved timesheets, with discounts, a client approval flow and PDF output. Expense claims carry receipt uploads and go through reimbursement. Reports cover utilisation, profitability and financial summaries.

  • Client approvals
  • Receipts
  • Payroll export API

Compliance & Alerts

The I-9 workflow tracks each case from initiation to approval, alongside E-Verify. Assignments can't start without an MSA and SOW, and visas are checked on approval. Daily jobs warn about expiring visas, passports, I-94s and driver's licences.

  • I-9 / E-Verify
  • Expiry alerts
  • Rules engine

Recruiting, ATS & Bench Sales

Covers job requisitions, candidates and interviews, job board postings and VMS submissions. Recruiters also get mass mail campaigns, bench hotlists, targets and a training course catalogue.

  • ATS
  • VMS submissions
  • Hotlists

Configurable RBAC & Audit

Admins create custom roles from a live permission catalog, and that catalog decides which menu items each person sees. Each person's access is checked on every API request. Every state-changing action is written to the audit log.

  • Custom roles
  • Self-scoped data
  • Full audit log

AI & Agents

AI that does the work, with a human approving every change.

Worq360 has two AI surfaces. AskMe is built into the app for questions, data lookups and document auto-fill. The standalone Agentic App is a Python multi-agent system: ten specialist LangGraph agents that call more than 140 tools through the Model Context Protocol. Agents can read anything the user is allowed to see. Before any write, the agent stops and waits for a human to approve it.

Approval required

Send invoice INV-0042 to the client?

The LangGraph task pauses in the input-required state, saved in a Postgres checkpoint, until someone approves or rejects it. Small invoices and expenses can be auto-approved below a dollar limit the admin sets. If that limit can't be checked, the agent asks for approval anyway.

10 MCP tool servers

FastMCP servers for HR, finance, recruitment, compliance, support, DevOps, budget, security, read-only SQL and external APIs. They call the same REST API the app's own screens use, so agents get no hidden backdoor.

Google A2A protocol

A JSON-RPC 2.0 API with tasks/send, sendSubscribe for streaming, get and cancel. An AgentCard lets clients discover the agents, and SSE streams each step live to the Agent Activity panel.

Agents act as the user

The user's own JWT is passed through every MCP call to the API, so an agent can never see or do more than the person chatting. The token is removed before the tool's input is checked, so the model never sees it.

Long-term semantic memory

After each conversation, the agent saves useful facts, such as a client's preferences and standing instructions, as Voyage embeddings in pgvector. Near-duplicates (cosine ≥ 0.92) strengthen an existing memory instead of adding a new one. The owner of each memory is set by the server, never by the model.

RAG with citations

AskMe answers questions from help docs and from published company documents such as policies, the handbook and benefits guides. Each answer cites the document and page, and only documents meant for the asker's role are used.

Natural language → SQL

Ask about your data in plain English. The question becomes a parameterized, read-only SQL query through a dedicated MCP server, and AskMe's Data mode uses tool calling for scoped lookups.

Vision & document extraction

Claude Vision checks timesheet hours against client screenshots. It also pulls fields out of uploaded IDs, contracts and SOWs, classifies document types, and fills in forms automatically.

Proactive agents

The Budget and Security agents scan every day. They pull Azure Cost Management data, Dependabot and CodeQL findings, and resource usage. Then they raise savings and security recommendations and alert on cost spikes, without anyone asking.

LLM business rules engine

Admins write business rules in plain English, and Claude Haiku checks submissions against them. A blocking rule stops a timesheet or expense from being submitted (HTTP 422).

Cost, reliability & observability

  • Anthropic prompt caching on agent system prompts and tool lists
  • A smaller, cheaper model handles routing and memory extraction
  • Claude is the main model, with an optional self-hosted Qwen3 fallback through Ollama
  • Rate limits of 60 requests per user per hour and 600 overall, checked before a stream opens
  • Every agent run is traced in LangSmith

AI in the delivery pipeline

  • Feature Factory: a 9-agent Claude Code pipeline (research → story → plan → backend → frontend → tests → validate → deploy) with three points where a human signs off
  • Sentry → GitHub triage: production errors arrive by webhook, duplicates are merged, and a GitHub issue is opened automatically
  • IT tickets from chat: tickets open GitHub issues and close themselves when the issue is closed (HMAC-signed webhook)
  • AskMe stays current: CI fails if a new route has no help doc or What's New note

System Architecture

One cluster. Two apps. One source of truth.

A TypeScript platform and a Python agent system run side by side on Azure Kubernetes Service, and both go through the same API and the same permission checks. Pick a layer, or tap the diagram, to see what it's built with.

Frontend

Two Angular apps: the main Worq360 app and the Agentic App. Both are built from standalone components with signals.

  • Angular 22, strict TypeScript, signal() and inject()
  • Angular Material; menus built from the user's live permissions
  • Route guards, plus interceptors that refresh the JWT
  • Socket.io notifications; SSE agent stream with approval cards

Backend API

A NestJS modular monolith: one API made of 37 feature modules, each with its own controllers, services and DTOs.

  • NestJS 11 and TypeORM, written in TypeScript
  • Short-lived JWTs, refresh tokens stored hashed, bcrypt and account lockout
  • Strict DTO validation, including custom SSN, routing-number and phone validators
  • Helmet, a request throttler, scheduled alert jobs and an audit service

Agent Layer

A separate Python workspace for the multi-agent system, deployed as its own set of pods.

  • FastAPI, LangGraph and LangChain-Anthropic
  • A2A JSON-RPC with SSE streaming
  • 10 FastMCP servers (streamable HTTP)
  • AsyncPostgresSaver checkpoints and LangSmith traces

Data & AI

One PostgreSQL database holds the business records, the vector embeddings and the agents' saved state.

  • Azure Database for PostgreSQL Flexible Server
  • pgvector for help-doc RAG, company-doc RAG and agent memory
  • Private Azure Blob containers for documents and receipts
  • Claude Sonnet for reasoning and Haiku for fast, cheap tasks

DevOps & Deployment

Each deploy writes the image SHA it shipped back into the Kubernetes manifest in git, so git always shows what is running.

  • AKS and ACR, with images built for both amd64 and arm64
  • 18 GitHub Actions workflows that sign in to Azure through OIDC, with no stored keys
  • nginx Ingress, with Let's Encrypt certificates from cert-manager
  • Network policies that deny traffic by default, plus Sentry for errors

required check

CI that runs real migrations

GitHub Actions · pnpm

Every pull request runs a type check, the full migration chain on a fresh pgvector Postgres, then unit and integration tests. Merging into master is blocked until they pass. The suite has 270+ Jest spec files and 30+ pytest files.

defense in depth

Security by default

App · cluster · supply chain

Every route requires a JWT and a role check. Inputs are strictly validated and webhooks are HMAC-signed. Deploys sign in through OIDC with no stored keys, and cluster network policies deny traffic by default. Dependabot and CodeQL scan the code continuously.

Reusable deploy template

Every deploy builds one image for both amd64 and arm64, pushes it to ACR, and applies the manifest. It then commits the image SHA it shipped back into git. A separate workflow promotes images already verified in dev to production.

@tool
async def invoice_send(id: str) -> str:
    """[HITL] Send a draft invoice to the client.
    Pauses for human confirmation before executing, unless the invoice total
    is below the admin-configured invoice_auto_approve_below threshold."""
    threshold, total_amount = await _invoice_auto_approve_check(id)
    if threshold > 0 and total_amount is not None and total_amount < threshold:
        result = await call_mcp_tool(settings.mcp_finance_url, "invoice_send", {"id": id})
        return json.dumps(_with_auto_approve(result, total_amount, threshold))

    # LangGraph pauses the graph here; the A2A task moves to input-required
    approval = interrupt({
        "action": "invoice_send",
        "description": f"Send invoice {id} to the client?",
        "data": {"invoice_id": id},
    })
    if not approval.get("approved", False):
        return json.dumps({"canceled": True, "reason": "Action rejected by user"})

    result = await call_mcp_tool(settings.mcp_finance_url, "invoice_send", {"id": id})
    return json.dumps(result)
