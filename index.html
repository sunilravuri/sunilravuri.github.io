Engineering deep-dives

05 hard problems
rbac

Permissions as data, not code

Six default roles ship, but every role's permission-key set is admin-editable at runtime through a dedicated roles module. The alternative — permission checks hardcoded per endpoint — was rejected early because staffing orgs redefine who can see what constantly; that decision paid off across every later module.

agents

Eight-agent orchestration layer

A LangGraph orchestrator classifies intent and routes to eight domain agents (onboarding, time & expense, support, admin, devops, and others) each backed by its own MCP tool server. Agents interoperate over Google's A2A protocol and share a semantic long-term memory with an automatic-extraction, dedup-on-write pipeline.

The hard part wasn't any single agent — it was keeping the orchestrator's routing prompt in sync as tools were added to individual agents, since a mismatch only surfaces as live requests silently misrouting.

rules

LLM-gated state transitions

Timesheet and expense submission isn't a static form validator — it calls an LLM to evaluate business-rule conditions and returns blocking vs. warning-level findings, so rule logic can evolve without a backend redeploy.

infra

Two fully isolated clusters

Separate Kubernetes clusters for production and development — separate registries, separate databases, separate ingress — with multi-architecture container builds and path-filtered CI/CD so a frontend-only change doesn't trigger a backend rollout.

security

Hardening as a cadence, not a gate

Recurring structured audits across app and infrastructure layers — not a single pre-launch checklist. Findings (access-control gaps, secret exposure patterns, network-policy review) get fixed and re-verified against the live environment on a standing schedule.

testing

Test suite as a real gate

3,000+ backend and frontend tests enforced through a CI coverage threshold — strict enough that a legitimate merge has silently failed deploy on falling short of it, which shaped how test coverage gets tracked going forward.

Security cadence

audit trail
audit 01 App + infra review — closed a sensitive-field leak in an API response and tightened an auth-token expiry bypass, same day as the finding.
audit 02 Resource-level cloud review — closed exposed management ports, locked network access rules on secret stores, and moved a storage account behind a private endpoint.
audit 03 Network review — added a stable-egress NAT gateway and subnet-level network security group on the database tier for both clusters.
audit 04 App review — closed a recurring same-shape data-leak pattern (a sensitive field returned through an unrelated endpoint) found for the fifth time across services, plus a broken-object-level-authorization gap on client data.
standing Deliberate, tracked deferrals — a small number of hardening items (secret-rotation cadence, one network-policy layer) are open by conscious cost/risk tradeoff, not oversight, and get re-checked each cycle.
